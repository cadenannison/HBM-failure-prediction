## Slide 7
- WHY AI ENGINEERING IS DIFFERENT FROM SOFTWARE ENGINEERING
- 01
- Probabilistic, not deterministic
- "It works" is not binary — you measure performance thresholds, not correctness.
- 02
- Data is a first-class dependency
- A label-encoding error is a production bug, not an analytics afterthought.
- 03
- Models degrade over time
- Deployment is the beginning. Drift is real, frequent, and expensive to ignore.
- 04
- Experimentation is inherent
- Gates replace deadlines: proceed when criteria are met, not ship on Friday.
- CS 401R · L01 — Introduction
> Notes: This is the intellectual foundation of the course. Every stage gate and architectural choice traces back to one of these four properties. Ask: 'What happens when your feature store goes down? When the training data no longer reflects production reality?' These questions don't exist in traditional software. Spend 5 minutes here.

## Slide 26
- WHAT and WHY of LOCALSTACK?
- LocalStack is a local cloud emulator. It lets you run simulated AWS services on your laptop or in a container, so you can develop and test cloud applications without deploying every change to an actual AWS account.
- For example, an application that normally uses:
- Amazon S3
- AWS Lambda
- DynamoDB
- API Gateway
- Step Functions
- Can point its AWS SDK, CLI, Terraform configuration at LocalStack instead of AWS. LocalStack exposes AWS-compatible APIs, typically through a Docker container.
- Faster development
- Instead of repeatedly deploying code to AWS, you can create resources and run integration tests locally.
- Lower development cost
- Local testing generally avoids AWS usage charges, although LocalStack itself has free and paid tiers.
- Isolated environments
- Each developer or CI job can have its own disposable AWS-like environment. This avoids conflicts in shared development accounts.
- Easier automated testing
- LocalStack can run inside GitHub Actions, GitLab CI, Jenkins, CodeBuild, and other CI systems, enabling cloud-style integration tests before deployment.

## Slide 27
- WHERE IT FITS IN AN AWS WORKFLOW
- Important limitations
- LocalStack approximates AWS behavior, but it is not the actual AWS control plane or runtime. Differences can occur in:
- IAM and authorization behavior
- Networking and VPC behavior
- Service quotas and throttling
- Performance and scalability
- Newly released AWS features
- Complex interactions among managed services
- LocalStack is best viewed as a fast development and testing environment, not a complete replacement for testing in AWS.

- AI SKILLS ARE IN HIGH DEMAND
- CS 401R · L01 — Introduction
- AI-skilled roles command roughly a 25% wage premium over non-AI equivalents, and the Dice 2025 Tech Salary Report puts the premium for AI expertise at nearly 18% versus comparable tech roles (Coursera, Dice).

- Shift to Production: Companies desperately need Forward Deployed Engineers and AI/ML Specialists to move prototypes into production, implement strict LLM optimization (caching and routing), manage complex Retrieval-Augmented Generation (RAG) pipelines, and wire models to internal APIs.
- The premium-pay skill stack in 2026:
- LLM fine-tuning and adaptation. The scarcest and highest-paid capability. It separates model users from model builders.
- RAG (retrieval-augmented generation). The default enterprise pattern for grounding LLMs on private data.
- MLOps and production reliability. The deploy-and-keep-it-running layer. Blends ML with infra, which is why the talent overlap is thin.
- Evals and evaluation harnesses. The 2026 differentiator. Teams that cannot measure model quality cannot ship it safely.
- Agentic IDE fluency. Day-1 productivity with agentic tools such as Claude Code. Increasingly a screening filter, not a nice-to-have.
