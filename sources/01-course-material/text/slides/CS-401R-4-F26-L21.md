## Slide 6
- Defining Monitoring and Observability
- 6
> Notes: Q: When an alarm fires, what else must already be recorded for you to explain it?   First, vocabulary from the chapter.  Monitoring tells you when something is wrong: a threshold was crossed, or a service-level objective (SLO) is using up its error budget faster than planned. Monitoring catches the failure modes you already know about and cataloged.  Observability tells you why. A system is observable when it records enough about its own internal state that you can answer a question nobody thought to ask in advance, without shipping new code to collect more data.  Why does this matter more for AI? Because AI failures skew toward the unknown: a new prompt attack on a language model, a subtle shift in customer behavior, a chain of agent tool calls nobody predicted. The dashboards you built on launch day won't catch those. Observability covers the gap.  Observability isn't free: more telemetry, more storage, more care about what you sample. The chapter's advice is to decide deliberately where deep observability is worth paying for.

## Slide 14
- Why a good model goes bad
- 14
> Notes: If the code has not changed, why does accuracy fall?  A model is a snapshot of the relationship between inputs and outcome at training time. Four things break it. Data drift: the inputs change, for instance prices rise. Concept drift: the same inputs now mean something different, for instance a competitor launches and loyal-looking customers start leaving. Prediction Shift: the base rate of the outcome changes. And data quality breakage: a pipeline bug sends nulls or the wrong units. The first three are the world moving. The fourth is your own system failing, and it is the most common.

## Slide 17
- Training-Serving Skew vs Data Drift
- Training-serving skew occurs when there is a mismatch between the data the model was trained on and the data it immediately encounters in production.
- While environmental changes can contribute to this skew, it also includes any discrepancies between the two datasets, such as issues related to data preprocessing, feature engineering, and more.
- Data drift is usually a more gradual process encountered during model operations, while training-serving skew refers to the immediate post-deployment window.
- 17
> Notes: The difference: data drift refers to the gradual change in the input data distributions. Training-serving skew refers to the mismatch visible shortly after the start of the model production use and can include issues unrelated to the changes in the environment.  The similarity: in both cases, we refer to the changes in the input data. You might use similar distribution comparison techniques to detect input data drift and training-serving skew by contrasting production data with training.

## Slide 18
- Data/Feature Drift
- Data Drift is a change in the statistical properties and characteristics of the input data.
- It occurs when production data no longer looks like the data the model was trained on.
- This shift in input data distribution can lead to a decline in the model's performance.
- 18
- Example:
- A retail chain uses ML to predict how many products of a certain type they need to stock.
- The model was trained using historical sales data from the past few years.
- All historical data came from physical stores.
- The company starts emphasizing online sales with a new marketing campaign/app.
- Initially, online sales are only a small part of overall sales. But there is a surge in online sales and the model's performance drops.
> Notes: Data Drift is a change in the statistical properties and characteristics of the input data. It occurs when a machine learning model is in production, as the data it encounters deviates from the data the model was initially trained on or earlier production data.   This shift in input data distribution can lead to a decline in the model's performance. The reason is, when you create a machine learning model, you can expect it to perform well on data similar to the data used to train it. However, it might struggle to make accurate predictions or decisions if the data keeps changing and the model cannot generalize beyond what it has seen in training.

## Slide 21
- Prediction Drift
- When discussing data drift, we typically refer to the input features that go into the model.
- Prediction drift, in comparison, is the distribution shift in the model outputs.
- Data Drift  P(X), Prediction Drift  P(Y)
- The shift in model outputs can signal changes in the environment or issues with the model quality.
- Imagine that a fraud model predicts fraud more often or a pricing model now shows significantly lower prices.
- 21
> Notes: Prediction drift can signal many issues, from low-quality data inputs to concept drift in the modeled process.  At the same time, prediction drift does not always imply model deterioration. It can also occur if the model adjusts well to the new environment.  For example, if fraud attempts actually increase, the distribution of the predicted fraud cases will look different.  In this case, you could observe both feature and prediction drift without a decay in the model quality.  The difference: data drift refers to the changes in the model input data, while prediction drift refers to the changes in the model outputs. The similarity is that both data and prediction drift are useful techniques for production model monitoring in the absence of ground truth and can signal changes in the model environment.

> Notes: What is prediction drift, and why monitor it separately from the inputs?  Prediction drift is a change in the distribution of the model's output, here the churn probability. It is measured like data drift, using the same methods on one column. It earns its own alarm for three reasons. It needs no labels. It summarises the combined effect of every input change in the one number the business acts on. And it has direct operational cost: in this simulated example, the share of customers scored above 0.5 rises from 5.3 to 12.5 percent, so the retention team receives more than twice as many cases. Prediction drift does not tell you whether the model is wrong. The world may really have become riskier. It tells you to look.  If the model is fixed, its predictions depend only on the inputs. When the input distribution doesn’t change, the prediction distribution can’t change either. Concept drift doesn’t move predictions at all, which is exactly what your slide 22 shows: AUC collapsed while Score PSI stayed at 0.001.  In practice, though, you can see prediction drift without any data drift alert. That happens three ways:  Drift your per-feature checks miss. PSI on each column looks at one feature at a time. The combination of features can shift while every individual distribution looks stable. For example, the same mix of tenures and the same mix of plan types, but more long-tenure customers on the cheap plan. The model reacts to the combination, so the scores move even though every feature check stays green.  Drift in features you aren’t monitoring. Teams often watch only the top features. A shift in an unmonitored feature still moves the scores.  The model or pipeline changed, not the data. Examples: a new model version was deployed, recalibrated, or given a new threshold, or an upstream bug started filling a feature with defaults or wrong units (training-serving skew).   With LLM systems, the provider can update the model behind the same API name, and the same prompts produce different outputs. That’s why the prediction check earns its place. It’s one summary check on the column the business actually acts on, and it catches drift the per-feature checks miss.  The reverse also holds. Data drift often happens without prediction drift, when the shifted features barely matter to the model. A data drift alert therefore doesn’t always mean the model’s behavior changed, and a prediction drift alert means its behavior definitely did.

## Slide 27
- Two families of drift metrics
- Statistical tests
- “Could this difference be chance?”
- Returns p-value. Drift when p is below 0.05.
- Kolmogorov–Smirnov (numeric)
- Chi-square (categorical)
- Z-test (binary)
- Strength: Principled on small samples
- Watch out: On large samples, flags changes too small to matter
- Distances
- “How far apart are they?”
- Returns a score. Drift when the score is above a threshold.
- Population Stability Index
- Wasserstein
- Jensen–Shannon
- Kullback–Leibler, Hellinger
- Strength: Stable at any sample size; tracks the size of the change
- Watch out: The threshold is a judgement you must make
- 27
> Notes: PSI is one drift metric. What are the others, and how do they differ?  Drift methods fall into two families that answer different questions. A statistical test asks whether the difference between two samples could be chance. It returns a p-value, and you call drift when the p-value is small. The Kolmogorov-Smirnov test is the best known. A distance asks how far apart the two distributions are. It returns a score, and you call drift when the score passes a threshold you choose. PSI, Wasserstein and Jensen-Shannon are distances. The distinction matters in practice: a test becomes more sensitive as you add data, while a distance settles on a stable value. Evidently offers about twenty methods across both families.  Transition: Take the best-known test first.

## Slide 28
- Statistical-Distance Tests for Drift
- Kolmogorov-Smirnov test: The KS test is a nonparametric statistical test. This means it does not make any assumptions about the underlying distribution. The null hypothesis is that the two samples come from the same distribution. The KS test is applied to reject or accept it. It returns the p-value. If the p-value is less than 0.05, you can declare that there is strong evidence to reject the null hypothesis and consider the two samples different. That is, there is drift.
- Population Stability Index (PSI): Instead of a p-value, you get a number that can take any value from 0 and above. It also reflects the relative "size" of the drift: the larger the PSI value, the more different the distributions are. Practitioners commonly interpret the results as the following: PSI < 0.1: no significant population change, 0.1 ≤ PSI < 0.2: moderate population change, PSI ≥ 0.2: significant population change.
- Wasserstein distance (WD) is applied only to numerical features. By default, it shows the absolute value of data drift. Roughly speaking, it measures how much effort it takes to turn one distribution into another. Here is an explanation of the intuition behind WD: if drift happens in one direction (e.g., all values increase), the absolute value of the WD metric often equals the difference of means.
- Kullback-Leibler divergence, (KL) aka relative entropy, is another stat test for num and cat features. Like PSI, it returns a score that can serve as the measure of the drift. A KL score can range from 0 to infinity. A score of 0 tells that the distributions are identical. The higher the score, the more different the distributions are. Unlike PSI, it is not symmetric. In other words, you get different values when you swap reference and current distributions. The KL metric does not depend on the size of a sample.
- Jensen-Shannon distance: JS is based on Kullback-Leibler divergence with two major differences: It is always finite and symmetric. The square root of the JS divergence is often referred to as the Jensen-Shannon distance. JS distance returns a score between 0 and 1. "0" corresponds to identical distributions, and "1" is extremely different. This makes this metric very interpretable.

## Slide 38
- Summary: How to Pick the Right Approach
- The size of drift you want to detect. In some cases, you want to react only to large changes. In others, even to a minor one. The definition of "large" and "small" would vary based on your data.
- The size of the samples you will compare. You should factor this in since different tests give different results depending on the sample size. In healthcare use cases, you might have hundreds of objects; in payments, you might have millions.
- The cost of the model performance drops. If every mistake is expensive, you might want to pick a more sensitive test, even at the cost of false-positive alerts.
- You can still use some heuristics! Start with a problem you're trying to solve. Would domain knowledge guide the correct metric?
- If accuracy is key, pick KS. If you deal with cases where even a 1% drift is critical, you can choose the most sensitive test. Just control the sample size to make sure it is not too large. Depending on the size of the data drift, you can use statistical power analysis to pick the optimal sample size.
- If you want to detect reasonable drift, pick WD. You can set a threshold based on the number of standard deviations you assume the distribution should change by to qualify as "drift."
- If you are used to PSI, go for it. It can work fine for features where fluctuation is a norm and you only want to be alerted on significant changes. While there is no quantitative intuition, you can rely on historical data to set the threshold.
- If you care about data segments, monitor them separately. No test is perfect here. The smaller the segment, the harder it is to detect drift. If even a minor change is critical, monitoring segments separately from the rest of the dataset makes sense.

> Notes: Q: When drift fires, should a new model ship automatically?   Two ideas on this slide.   First, maturity gates what you can do. ## Slide 73
- Promotion: A/B Test or Bandit?
- 73
- A/B test: high stakes, auditable
- 5–10% of traffic to the challenger
- Success criteria fixed before the test
- Guardrail breach → automatic rollback
- Use for the churn model
- Bandit: many variants, lower regret
- Thompson sampling shifts traffic toward the leader
- Richer telemetry; harder to audit
- Use for offer prompt templates
- Lab 5's canary is the traffic-split mechanism either one uses.
> Notes: Q: Why not always use the faster method?   Before a retrained model gets all the traffic, validate it against the current model with real users.   A/B testing, from the chapter:  - Send 5 to 10 percent of traffic to the challenger and expand only on a statistically significant improvement with no guardrail damage.  - Fix the metrics, thresholds and duration before the test starts; setting them after seeing results undermines the test.  - Run long enough to cover the business cycle.  - If the challenger breaks any guardrail, roll back automatically.  - Fairness metrics need enough observations per segment, or small samples produce false alarms.   Multi-armed bandits generalize this. Instead of a fixed split, a bandit moves traffic toward the better-performing variant as evidence arrives, which reduces regret: the cost of sending users to the worse option while you learn. Thompson sampling does this by sampling from a probability distribution over each variant's performance and routing traffic in proportion to the chance each one is best. McClendon and colleagues found bandit-based deployment can match or beat A/B testing on decision speed and regret under some conditions.   The trade-off is auditability. Bandits need richer telemetry, careful guardrails and more complex rollback, and because allocation keeps changing, they're harder to audit. The chapter's rule: A/B for high-stakes decisions that must be auditable, like the churn model, which affects how customers are treated; bandits for evaluating many low-stakes variants, like offer prompt templates.   Either way, the traffic split is the same canary mechanism you built in Lab 5.   Transition: Whatever we promote has to be recorded, documented, and eventually retired.

- Three Types of Drift
- 84
> Notes: Q: Why does the type of drift matter for what we do next?   The chapter follows Gama and colleagues' survey and separates three things practitioners often blur together.   Data drift, also called covariate shift: the distribution of the inputs changes, but the relationship between inputs and the outcome stays the same. For NorthStar, holiday shopping pushes average order value up. You can detect this without any labels, using statistical tests on the features. The response is to investigate: is the shift permanent or temporary? Retrain only if it persists and actually hurts accuracy.   Concept drift: the relationship between inputs and outcome changes. The same purchase history now means something different. For example, a competitor launches a loyalty program and customers who look perfectly loyal start leaving anyway. You cannot see this from inputs alone. You need labels, or proxies, shadow models, and cohort monitoring, which is our next slide. The response is to retrain on the new regime and sometimes to revisit how the problem was framed.   Model degradation: the model's quality metrics decline. Data drift or concept drift usually causes it, but so can pipeline bugs and training-serving skew. Detecting it requires labels. For NorthStar that means our recall in the top 10 percent, measured when the 90-day labels arrive. The response depends on the cause: retrain, recalibrate, or redesign.   The navy box is the point people miss: data drift is not automatically a reason to retrain. If the model is still accurate on the new distribution, it is working. Treating every alert as "drift, therefore retrain" leads to the wrong intervention.   Lab 6 Task 2 asks which of the three is most likely for NorthStar. ## Slide 92
- What Is Embedding Drift?
- Understanding semantic distribution shifts in vector space over time
- 2 / 7
- Core Definition
- Embedding drift is a shift in the statistical distribution or geometric alignment of numerical vector embeddings over time, causing semantic changes and degraded downstream retrieval or model performance.
- Primary Root Causes
- ▪ Input Data Evolution: New customer vocabulary, emerging product categories, seasonal shifts, or upstream data quality issues.
- ▪ Preprocessing Changes: Modifications to text chunking size, metadata formatting, normalization, or prompt templates.
- ▪ Model Upgrades or Swaps: Updating embedding model weights or changing providers without re-indexing historical vectors.
> Notes: Let's start with a clear definition of embedding drift. At its core, embedding drift occurs when the statistical distribution or geometric alignment of your vector representations shifts over time. Because vector databases rely on geometric proximity (like cosine similarity) to represent semantic meaning, a shift in vector geometry directly degrades retrieval accuracy.  Walking through the visual on the right: - The teal cluster represents our baseline embeddings at time t0, centered around centroid mu_0. - Over time, incoming production data (shown in coral at time t1) migrates to a new region of the embedding space around centroid mu_1. - Even if your vector database is healthy and returning results with low latency, the nearest neighbors retrieved for a given query are no longer semantically optimal.  Three root causes typically drive this shift: 1. Input Data Evolution: Real-world language and behavior change—such as new slang, seasonal shopping trends, or corrupted upstream fields (e.g., null strings getting embedded). 2. Preprocessing Changes: Subtle engineering changes like altering chunk overlap, stripping punctuation, or changing how user attributes are serialized into text. 3. Model Upgrades or Swaps: Switching embedding models—even between minor versions—places vectors in an incompatible coordinate space if historical vectors aren't re-indexed.

## Slide 93
- General Detection & Measurement Toolkit
- Four complementary methods to quantify vector distribution drift
- 3 / 7
- 1. Distance & Similarity Metrics
- ▪ Centroid Shift: Track Euclidean (L2) or cosine distance between baseline and rolling production centers of mass.
- ▪ Maximum Mean Discrepancy: Use kernel-based MMD to test whether two multivariate vector samples come from the same distribution.
- ▪ Neighbor Stability: Monitor whether Top-K nearest neighbors for fixed benchmark queries change over time.
- 2. Dimensionality Reduction + Stats
- ▪ PCA / UMAP Projection: Compress high-dimensional vectors (e.g., 768–3072d) while retaining ~95% variance.
- ▪ Statistical Divergence Tests: Apply Kolmogorov-Smirnov (K-S), Population Stability Index (PSI), or KL divergence on top components.
- ▪ Component-Level Alerts: Pinpoint which principal semantic axes are experiencing significant distributional shifts.
- 3. Domain / Binary Classifier
- ▪ Adversarial Drift Detection: Train a lightweight classifier (e.g., logistic regression or GBDT) to separate baseline vs. current vectors.
- ▪ ROC-AUC as Drift Score: An AUC near 0.50 means distributions are indistinguishable; high AUC (>0.70) confirms structural drift.
- ▪ Feature Attribution: Inspect misclassified or high-confidence samples to isolate emerging data clusters.
- 4. Visual & Downstream Proxies
- ▪ 2D Cluster Inspection: Project vectors with UMAP or t-SNE to visually spot emerging pockets, outliers, or sparse regions.
- ▪ Retrieval Quality Proxies: Correlate vector shifts with drops in Recall@K, MRR, or outlier distance scores.
- ▪ Business Outcome Validation: Verify whether mathematical drift actually degrades end-user conversions or accuracy.
> Notes: Because embeddings typically live in 768 to 3,072 dimensions, you cannot detect drift by inspecting raw numbers. Instead, we combine four complementary families of techniques:  1. Distance and Similarity Metrics: This is the fastest, lowest-overhead approach. By tracking the centroid (center of mass) of rolling production embeddings against a baseline window, or computing Maximum Mean Discrepancy (MMD), we get a real-time pulse on global vector movement. 2. Dimensionality Reduction + Statistical Tests: Standard univariate tests like Kolmogorov-Smirnov (K-S) or Population Stability Index (PSI) struggle in thousands of dimensions due to the curse of dimensionality. Projecting vectors down via PCA (retaining ~95% variance) lets us apply proven statistical tests to the top principal components. 3. Domain / Binary Classifier: Also known as adversarial validation. You label baseline embeddings as '0' and recent production embeddings as '1', then train a fast classifier. If the classifier achieves an ROC-AUC near 0.50, the distributions are identical. If AUC climbs above 0.70, the model easily separates new data from old—proving drift has occurred. 4. Visual & Downstream Proxies: Mathematical drift is sometimes benign (e.g., harmless phrasing variations). Pairing UMAP visualizations with downstream business metrics ensures we only trigger engineering interventions when drift hurts real-world performance.

- Practical Detection Pipeline & Best Practices
- Four operational patterns to isolate true drift and avoid blind spots
- ▪ Golden Canary Evaluation Set: Maintain 100–200 fixed customer profiles paired with ideal offers. Run daily; if Top-K IDs or scores shift without catalog edits, drift is confirmed.

Segment-Level Tracking: Never rely solely on a single global average across all traffic. ## Slide 101
- Population Stability Index (PSI)
- Measures how much a variable’s distribution changes between the reference data set (e.g., training data) and the current data set (e.g., this month’s data)
- How the calculation works
- 1. Choose bins using the reference data.
- 2. Use the same bins for current data.
- 3. Calculate each bin’s proportions.
- 4. Sum the bin contributions.
- PSI formula
- Cᵢ = current proportion in bin i
- Rᵢ = reference proportion in bin i
- ln = natural logarithm
- Numeric features: fixed ranges
- Categorical features: shared categories
- PSI = 0: identical binned distributions. Larger values indicate more change.
> Notes: Purpose and framing (about 3 minutes) PSI stands for Population Stability Index. It compares the distribution of one variable in a reference population with that variable’s distribution in a current population. A typical reference is training data or an approved production baseline. A current window might contain this month’s production observations. PSI can also monitor a model’s score distribution. It does not need ground-truth outcome labels.  Calculation walkthrough First define mutually exclusive bins that cover the feature’s possible values. Numeric bins may use reference quantiles or meaningful fixed ranges. Categorical features use aligned categories. Keep the same boundaries and category mapping for both populations. Recomputing quantile bins separately for each dataset can hide change. Divide each bin’s count by the total observations in its own dataset. Each distribution must sum to one, even when sample sizes differ. Use fractions such as 0.50 rather than 50 in the formula.  For each bin, subtract the reference proportion from the current proportion, then multiply by the natural logarithm of their ratio. Sum over all k bins. If a bin is unchanged, its contribution is zero. If its proportion increases, both factors are positive. If it decreases, both factors are negative, so the contribution is again nonnegative. Thus increases and decreases do not cancel.  Implementation details A zero in either distribution makes the logarithm or ratio undefined. Apply a documented smoothing method consistently, such as adding a small pseudocount to every bin in both datasets and then renormalizing. Record the method because smoothing affects the result, particularly for rare categories. Handle missing values explicitly and consistently, often in a separate bin. Bin count, boundaries, sample size, and rare categories all affect interpretation.  Teaching check Ask: If the current dataset has twice as many records but exactly the same proportions, what is PSI? Answer: zero. PSI compares proportions, not raw counts.  Source: explanation and illustrative data supplied in this conversation. No external empirical dataset is used.

## Slide 102
- PSI worked example: NorthStar customers
- Purchase-frequency distribution: reference data versus this month’s production data
- Low bin: (0.30 − 0.50) × ln(0.30 / 0.50) = 0.1022
- PSI = 0.2408
- More customers fall in the high-frequency group.
- This signals a change in the customer mix.
- Thresholds are rules of thumb.
- PSI provides no p-value and does not prove that accuracy has declined.
> Notes: Worked example (about 3–4 minutes) This is an illustrative NorthStar example, not measured production data. We monitor customer purchase frequency using three consistent groups: low, medium, and high. The reference distribution is 50%, 30%, and 20%. The current distribution is 30%, 30%, and 40%. The medium group is unchanged, while the population shifts from low to high frequency.  Arithmetic For the low bin, C minus R is −0.20, and ln(0.30/0.50) is approximately −0.510826. Their product is 0.102165. For medium, the difference is zero and ln(1) is zero, giving a zero contribution. For high, the difference is 0.20 and ln(0.40/0.20) is ln(2), approximately 0.693147. Their product is 0.138629. Add the unrounded contributions to obtain approximately 0.240795, displayed as 0.2408. Each population’s proportions sum to 100%.  Interpretation Common heuristics describe below 0.10 as little change, 0.10 through 0.25 as moderate change, and above 0.25 as substantial change. These are conventions rather than universal or statistically derived cutoffs. Under the displayed convention, 0.2408 indicates moderate change near the upper boundary. Use thresholds appropriate to the feature, sample size, operational context, and historical variation. A system may deliberately use a different investigation threshold.  Operational response Inspect which bins contributed most. Here, high and low purchase frequency drive the score. Check for a changed customer mix, a campaign, seasonality, a change in how purchases are counted, or an upstream data issue. Compare sample sizes, missingness, data quality, and relevant customer segments. Review model outcomes when labels arrive before concluding that performance has degraded. Retraining is a decision after investigation, not an automatic consequence of this score.  Limits PSI is a descriptive drift score and produces no p-value. An unchanged binned distribution yields zero, but binning can hide changes within bins. Per-feature PSI also misses changes in relationships between variables. Data drift does not necessarily imply worse predictions: a different mix of customers may still be handled well by the model. Conversely, accuracy can deteriorate even when an individual feature’s PSI is small.  Discussion prompt Ask: Does 0.2408 prove the churn model is less accurate? Answer: no. It demonstrates a shift in this feature’s binned distribution. Accuracy requires a separate evaluation using labeled outcomes. > Notes: Q: What kind of failure passes every health check we have built so far?   Two patterns that hide even when all five layers are instrumented.   Left: aggregates hide slices. Johnson and colleagues showed that headline metrics routinely mask serious degradation for specific groups. A model can meet its overall accuracy target while failing badly for the customers the business cares about most. So the model layer needs metrics by slice, or segment, next to the overall numbers.   And always show the sample size, written n. Our own example: on an earlier, smaller NorthStar dataset, the Platinum loyalty tier had about 33 customers in the test set and only 2 churners. Common causes: time zones and timestamps handled differently, a 30-day window in training but a 7-day window in serving, the wrong feature-store version, or preprocessing that behaves differently in batch and streaming code.   Skew is sneaky because the model's outputs stay in normal ranges. Every health check passes; the predictions are just built on subtly wrong inputs. The detection method is the same comparison Evidently already runs for drift: training distribution versus inference distribution, feature by feature.   Transition: Time to practice. > Notes: Q: How do we choose a test for each feature, and how would we know it's wired correctly?   Four families of tests from the chapter.   PSI, the Population Stability Index, is the workhorse because it gives one interpretable number per feature. Yurdakul's starting heuristics: below 0.1 suggests stability, 0.1 to 0.25 moderate drift, above 0.25 significant drift. The book and Lab 6 alert at 0.2, a common rule of thumb inside the moderate band. Important: these thresholds have no defined statistical error rate. They are starting points to calibrate, and the right value depends on how you bin the data, sample size, feature type and business context. Jensen–Shannon (JS) divergence works well for categorical features.   For embeddings, the high-dimensional vectors that language models produce, teams watch the distance between centroids over time, shifts in nearest-neighbor distributions, or Maximum Mean Discrepancy (MMD).
