Form the team

Pick one owner per workstream. Owners also draft the doc sections their steps produce.

Done whenEvery workstream has a name next to it.

Set up the repo

Start from your lab repo layout (infrastructure/, glue-scripts/, scripts/, docs/). Add data/ to .gitignore and write a README with the run commands.

Get the data

git clone https://github.com/wrl297/Calchas.git

Copy Data/raw_data into your raw folder and Data/processed_data into a reference folder. Record the commit hash so your lineage points to an exact version.

Done when20,391 raw events and the four processed tables load in pandas.

Define

steps 4–5
4

Explore the errors

Look at the error mix by type (CE, UEO, UER), errors per server, time between errors, and how errors cluster on the same row, column and bank.

Done whenAn EDA notebook with a short written summary of what seems to come before a UE.
Lead + modeling
5

Define the task and metrics

Write down what counts as a failure, the observation and prediction windows, and the four prediction levels. Match each level to its action: row to retire row, bank to spare bank, server to drain. Set a recall floor and precision target per level. Start with the paper's windows so your results compare.

Done whenA one-page task spec the whole team agrees on.
Lead Economics & governance Feeds: problem statement, success metrics
SplitFrom here the pipeline (steps 6–9) and a first modeling pass on the processed tables (step 10) run at the same time.

Pipeline

steps 6–9
6

Stand up the platform

Reuse your Terraform modules: VPC, encrypted S3 with raw, processed and features prefixes, IAM, VPC-only SageMaker, Glue and Feature Store. Add a FleetOps role that can read predictions and nothing else.

terraform -chdir=infrastructure/environments/dev plan -out=hbm.tfplan
terraform -chdir=infrastructure/environments/dev apply hbm.tfplan
Done whenThe apply succeeds and your verify script passes.
Data & platformFeeds: platform architecture
7

Write the data contract

Schema, allowed EccType values (CE, UEO, UER), valid hex addresses, no future timestamps, and a dedupe rule. Turn each rule into a quality gate that fails the job.

Done whenThe gates catch a deliberately broken file.
Data & platformFeeds: data & feature pipeline
8

Build the feature job

A Glue job that turns raw error events into windowed features per row, column, bank and server: CE and UE counts, distinct rows, columns and cells, and time since the first CE.

Done whenThe job writes Parquet to features/ straight from the raw logs.
Data & platformFeeds: data & feature pipeline
9

Load the Feature Store

Offline store for training, online store for scoring. Spot check your counts against the paper's processed tables.

Done whenEvery entity is in the offline store and the spot checks match.
Data & platformFeeds: data & feature pipeline

Models

steps 10–12
10

Train baselines

Logistic regression, random forest and XGBoost per level, with class weights for the 0.3–0.7% positive rate. Log every run in MLflow.

Done whenMLflow shows a baseline score for each level.
Lead + modeling
11

Split by time and tune

Train on earlier months of your raw-log features and test on later ones. The processed tables have no timestamps, so use them only as a second track. Pick a threshold per level from the precision-recall curve and the cost of each action, then benchmark against the paper's F1: row 0.78, column 0.79, bank 0.70, server 0.42.

Done whenA best model per level is chosen, and it either beats the paper or you can explain the gap.
Lead + modeling
12

Write the model card

Data, metrics per level, thresholds, and known limits: 50 servers, anonymized fields, one HBM generation.

Done whenModel card v1 is in docs/.
Lead + modelingFeeds: model development

Ship

steps 13–16
13

Add a registry and approval gate

Register candidates in MLflow or the SageMaker Model Registry. Nothing reaches scoring without a human approval.

Done whenYou can move a model from candidate to approved by hand.
XOps & deploymentFeeds: XOps plan
14

Automate retraining and tests

A SageMaker Pipeline that runs features, train, evaluate, register. CI runs the data contract tests plus model tests: a recall floor per level and no regression against the current champion.

Done whenOne pipeline run registers a model, and a deliberately bad model gets blocked.
XOps & deploymentFeeds: XOps plan
15

Score in batch

An hourly job reads the online features, scores each level, and maps scores to actions by confidence: retire row, spare bank, or drain server.

Done whenOne end-to-end run writes action recommendations.
XOps & deploymentFeeds: deployment strategy
16

Plan the rollout

Shadow first (log actions, take none), then advisory (operators approve each one), then automatic for row retirement only. Server drains always need a human.

Done whenEach rollout stage has written exit criteria.
XOps & deploymentLeadFeeds: deployment strategy
SplitSteps 17–19 run in parallel once scoring works. The economics owner can start step 18 as early as step 5.

Operate & justify

steps 17–19
17

Set up monitoring and SLOs

Watch input drift (CE rate per server, temperature), the prediction mix, and precision and recall once labels arrive. Define SLOs, alerts and a runbook. The fallback is the hardware's normal ECC and sparing.

Done whenA dashboard spec, an SLO table and a runbook exist.
XOps & deploymentFeeds: operating model
18

Build the cost model

Crashed job cost = accelerators × hours since the last checkpoint × cost per accelerator-hour. Compare it against the cost of each action, the cost of false alarms, and AWS spend. Show ROI with a sensitivity table on false alarm rate.

Done whenEvery number in the economics section comes from one spreadsheet.
Economics & governanceFeeds: economic justification
19

Write the governance framework

Automation tiers per action, human sign-off for drains, an audit trail (prediction, model version, action, approver), data anonymization rules, and a model card review on every release.

Done whenThe governance section includes a RACI table.
Economics & governanceFeeds: governance framework

Finish

steps 20–22
20

Assemble the doc

One section per course layer plus the architecture diagram. Each owner brings in what their steps produced.

Done whenAll eight sections have content.
Whole team
21

Review and rerun

Each owner reviews someone else's section against the rubric. Rerun the final numbers so every figure in the doc matches the code.

Done whenNo open review comments, and the numbers match.
Whole team
22

Tear down and submit

Destroy the NAT gateway, SageMaker domain and Glue jobs before they keep billing, then submit.

Done whenterraform destroy is clean and the doc is turned in.
