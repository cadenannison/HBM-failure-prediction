Week by week

What gets built, what proves it is done, and which design doc sections it feeds.

W1

Kickoff and data

Nov 2–6
  • Form the team, assign owners, and set up a shared repo that reuses the lab Terraform layout.
  • Clone the dataset and run EDA: error mix (CE, UEO, UER), errors per server, clustering by row, column and bank, and time between errors.
  • Lock scope: what counts as a failure, observation and prediction windows, and target recall and precision per level.
Milestone
Scope locked, EDA notebook

W2

Platform and feature pipeline

Nov 9–13
  • Terraform: S3 raw, processed and features prefixes; IAM roles (DataEngineer, MLEngineer, ModelMonitor, plus a FleetOps consumer); VPC-only SageMaker.
  • Glue job turns raw error events into windowed features per row, column, bank and server: CE and UE counts, distinct rows, columns and cells.
  • Data contract and quality gates: valid hex addresses, known ECC types, no future timestamps, deduplicated events.
  • Load features into Feature Store and sanity check them against the paper's processed tables.
Milestone
Pipeline runs end to end on raw logs
Feeds
Platform architectureData & feature pipeline
W3

Model development

Nov 16–20
  • Baselines per level (logistic regression, random forest, XGBoost) with class weights for the 0.3–0.7% positive rate.
  • Two tracks: the paper's processed tables (include temperature and power) and your raw-log features, which allow a time-based split with no leakage.
  • Tune a threshold per level and compare F1 to the paper: row 0.78, column 0.79, bank 0.70, server 0.42.
  • Log every run in MLflow.

W4

XOps and deployment

Nov 23–27 · short week
  • Register the best models behind an approval gate; SageMaker Pipeline for features, train, evaluate, register.
  • Hourly batch scoring that maps each score to an action by level and confidence: retire row, spare bank, or drain server.
  • CI with data tests and model tests: recall floor per level, no regression against the current champion.

W5

Operations, economics, governance

Nov 30–Dec 4
  • Monitoring: input drift (CE rate, temperature), prediction mix, precision and recall from lagged labels; SLOs and an on-call runbook.
  • Cost model: crashed-job cost (accelerators times hours since checkpoint) against row spare, bank spare and drain costs, plus AWS spend; ROI with a sensitivity table on false alarm rate.
  • Governance: automation tiers, human sign-off for server drains, audit trail, data anonymization, model cards.

Team pitch

Paste this wherever you are recruiting.

I'm putting together a team for the CS 401R design doc and looking for 3 people. The project is an AI system that predicts HBM memory failures in an AI data center before they crash multi-day training jobs. It watches for warning patterns in correctable errors, then acts based on risk: retire a bad row, spare a bank, or move the job off a failing server. The data is already verified: a public dataset of about 20,000 real HBM error events from 8 data centers (USENIX ATC 2024), only 24 MB, clean, labeled, and with published benchmarks to beat. It reuses everything from our labs (Terraform, Glue, Feature Store, SageMaker, MLflow), and there's a 6-week plan ready to go. I'll own scope and modeling. I need one person each for data and platform, XOps and deployment, and economics and governance. Message me if you're in.

Data: Calchas HBM error dataset, from Wu et al., “Removing Obstacles before Breaking Through the Memory Wall: A Close Look at HBM Errors in the Field,” USENIX ATC 2024. Benchmark F1 scores are the paper's reported results.
